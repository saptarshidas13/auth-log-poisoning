# Legitimate-Only Poisoning of Log-Driven Authorization Learning

Code accompanying the paper of the same title. It studies an insider who only
exercises permissions they already legitimately hold, in a deliberately chosen
pattern, and shows this is enough to manipulate what a log-driven authorization
learner grants, retains, or removes, without forging a single record or flipping a
single label. The repository contains the full experimental pipeline: the ABAC rule
miners and their attacks, the MLBAC/DLBAC classifier and its attacks, the
least-privilege retention attack, the certified-robustness defense, and every script
used to produce the paper's tables and figures.

## Repository layout

```
src/
  abac/         ABAC policy model, .abac file parser, log construction, coverage/metrics
  miners/       Bottom-up rule miners: strict (Xu-Stoller), sparse-log (Rhapsody),
                and the SACMAT 2026 domain-based (MDL) miner, reimplemented from its
                published description
  attack/       Threat model, the greedy rule-generalization attack, MLBAC clean-label
                poisoning, retention poisoning, and evaluation/analysis helpers
  mlbac/        DLBAC-style classifier, training/evaluation, and dataset loading
  defense/      Certified-robustness check (full-population soundness)
  tightening/   Log-driven least-privilege tightening tool and its retention criterion
  pipeline/     Shared ExperimentRecord/ResultsWriter schema used by every experiment
  experiments/  One script per reported result (see "Reproducing the results" below)
  metrics.py    Over-privilege / under-privilege / rule-count comparison against P*
generate_figures.py   Regenerates the four paper figures from results/*.csv
requirements.txt
```

`results/`, `figures/`, and `datasets/` are not tracked in this repository (see
`.gitignore`); the first two are regenerated by running the code, and the third is
populated by the setup step below.

## Setup

Requires Python 3.9+ (developed and tested on 3.14). All experiments run on CPU only;
no GPU is required or used anywhere in this repository.

```bash
python -m venv .venv
source .venv/bin/activate        # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Datasets

Only two upstream sources are used, both pinned to the exact commit this codebase was
built and evaluated against. Clone them into `datasets/` at the paths below (the
directory structure must match exactly; the experiment scripts hardcode these paths
relative to their own file location, so they work regardless of your current working
directory as long as this layout is preserved).

```bash
mkdir -p datasets/1_abac_ground_truth datasets/3_dlbac_synthetic

git clone https://github.com/ABAC-Lab-Admin/ABAC-Lab.git datasets/1_abac_ground_truth/ABAC-Lab
git -C datasets/1_abac_ground_truth/ABAC-Lab checkout 3539fc9cc153f6084f9590f0aa08dca00d105fe2

git clone https://github.com/dlbac/DlbacAlpha.git datasets/3_dlbac_synthetic/DlbacAlpha
git -C datasets/3_dlbac_synthetic/DlbacAlpha checkout 261df3eacc455f6c9adbba1338b9280bfd2aaf09
```

This provides:
- `datasets/1_abac_ground_truth/ABAC-Lab/DATASETS/abac-datasets/{university,healthcare,project-management,workforce,edocument}.abac`
  five ground-truth ABAC policies with known `P*` (Karimi et al., "ABAC Lab," SACMAT 2025).
- `datasets/3_dlbac_synthetic/DlbacAlpha/dataset/synthetic/<name>/{train,test}_<name>.sample`
  eight synthetic DLBAC benchmarks (Nobi et al., "Toward Deep Learning Based Access Control," CODASPY 2022).
- `datasets/3_dlbac_synthetic/DlbacAlpha/dataset/real-world/{amazon1,amazon2,amazon3}/{train,test}_<name>.sample`
  three DLBAC-formatted instances of the Amazon Employee Access Challenge (Kaggle), reused as-is
  from the DLBAC authors' repository, no separate Kaggle download needed.

No other dataset is used by any script in this repository.

## Reproducing the results

Run scripts from anywhere; each resolves `datasets/` and writes `results/` relative to
its own location (two directories up from `src/experiments/`). Example invocation:

```bash
python src/experiments/pipeline_p1_rule_generalization.py
```

| Script | Produces | Paper location |
|---|---|---|
| `pipeline_p1_rule_generalization.py` | `results/p1_rule_generalization.csv` | Table 2, Fig. 2 (phase transition), RQ3/RQ4 rows |
| `pipeline_p1_edocument_direct.py` | `results/p1_edocument_direct.csv` | Table 2's edocument rows (direct targeted sweep) |
| `pipeline_p1_multi_target_sweep.py` | `results/p1_multi_target_sweep.csv` | RQ1 exploit-rate breakdown, RQ2 correlation, Fig. 3, supplementary Table S1 |
| `fix_rq4_stealth.py` | `results/p1_rq4_stealth_corrected.csv` | Table 3 (stealth z-scores) |
| `phase6_dbpm_attack_demo.py workforce` | console output only | Section 4.5/8: single-record flip of the domain-based (MDL) miner on workforce |
| `phase6_dbpm_multi_target.py` | `results/p1_dbpm_multi_target.csv` | Domain-based-miner multi-target exploit rate (Section 8, supplementary Table S1) |
| `pipeline_p2_mlbac.py` | `results/p2_mlbac.csv` | Supplementary Table S3 (synthetic MLBAC sweep) |
| `pipeline_p2_mlbac_coalition_realworld.py` | `results/p2_mlbac_coalition_realworld.csv` | Section 8.7's real-world coalition result (see caveat below) |
| `pipeline_p3_retention.py` | `results/p3_retention.csv` | Section 8.8 (retention poisoning, 100/100 trials) |
| `pipeline_p4_certified.py` | `results/p4_certificate.csv` | Theorem 1/2 stress test, Fig. 4 (utility tradeoff), Table S2 |
| `phase7_ablation_group_size.py` | `results/p7_ablation_group_size.csv` | Fig. 5 (coalition-composition ablation) |

Run all of them (each is independent and writes its own output file, so they may be run
in any order or in parallel) to populate `results/`, then:

```bash
python generate_figures.py
```

to regenerate `figures/fig_phase_transition.pdf`, `fig_rq2_validation.pdf`,
`fig_utility_tradeoff.pdf`, and `fig_coalition_ablation.pdf`.

### Expected runtime

All mining and training runs on a single CPU core; no script needs a GPU. Approximate
per-call costs, from the paper's own runtime table:

| Component | Scale | Typical cost |
|---|---|---|
| Xu-Stoller / Rhapsody mining call | university/healthcare/project-management (n≈20-60) | <0.1 s |
| Xu-Stoller / Rhapsody mining call | workforce (n≈600) | 5-8 s |
| Xu-Stoller / Rhapsody mining call | edocument (n≈800) | 5-60 s |
| Domain-based (MDL/AutoPart) mining call | workforce/edocument | 40-90 s |
| Domain-based (graph-coloring, clean) mining call | any scale | <1 s |
| MLBAC MLP training call (10 epochs) | 9k-26k rows | 2-6 s |

`pipeline_p1_multi_target_sweep.py` is the longest-running script (it performs several
thousand mining calls across three fast datasets plus a handful of slow calls on
workforce/edocument); expect it to take on the order of tens of minutes.

## Reproducibility notes

- **A cross-process non-determinism bug was found and fixed mid-project** in
  `src/abac/schema.py`: its attribute-domain accessors used to return bare Python
  `set` objects, whose iteration order depends on the interpreter's per-process hash
  seed, feeding into the greedy conjunct-drop order during rule generalization. The
  code in this repository already contains the fix (`sorted(...)` results), and is
  cross-process deterministic: running any script twice, as separate processes,
  produces identical output.
- **This means results generated before the fix (Table 2, Table 3, Fig. 2, Fig. 3,
  Fig. 4, i.e. everything produced by `pipeline_p1_*.py`, `fix_rq4_stealth.py`, and
  `pipeline_p4_certified.py`) may not reproduce bit-for-bit against the exact numbers
  quoted in the paper.** The current, fixed code finds a different, equally valid
  locally-optimal rule generalization than the pre-fix code happened to find, which
  can shift specific poison-size or z-score values while preserving every qualitative
  finding (which datasets are exploitable, the direction and rough magnitude of every
  effect, the certificate holding at zero violations, and so on). Results from
  `phase7_ablation_group_size.py` onward were generated after the fix and are exactly
  reproducible.
- **`pipeline_p2_mlbac_coalition_realworld.py` reconstructs, rather than replays, the
  paper's real-world MLBAC coalition result.** The original interactive exploration
  that produced the paper's quoted figures (66 users, 168 pooled rows, 100 poisoned
  rows) was not saved as a script. This script implements the same methodology
  (Algorithm 3: pool a coalition's legitimate rows, rank by proximity or gradient
  alignment, binary-search the minimal prefix) with a documented, deterministic
  coalition-selection rule (fewest-legitimate-rows-first). On verification it
  reproduced the qualitative finding exactly, the beneficiary's own row is not enough
  to flip the target alone, while the pooled coalition succeeds, but found a smaller
  minimal poison size than the paper quotes, because the specific denied target this
  rule selects is not the same one the original exploratory run used, and the
  exploit rate is known (from the paper's own multi-target sweep) to vary widely by
  target. Treat its poison-size output as a demonstration of the mechanism, not a
  bit-exact replication of the quoted headline number.
- All pseudo-random number generators used anywhere in this codebase are explicitly
  seeded; no script depends on wall-clock time or external state for its numeric
  results.
